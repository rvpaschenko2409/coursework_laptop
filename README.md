# Выбор ноутбука для сотрудников

Курсовая работа. Вариант 27.

## Цель
Разработать систему поддержки принятия решений для выбора
ноутбука под требования сотрудников с прогнозом производительности
по техническим характеристикам.

## Методы
- DEMATEL — анализ взаимного влияния критериев.
- MEREC — определение весов критериев.
- MARCOS и VIKOR — сравнение и ранжирование ноутбуков.

## Технологии
Расчётный прототип: Python, pandas, NumPy, scikit-learn.
Для приложения предусмотрены FastAPI, PostgreSQL и PWA либо MAX.
Эти компоненты приложения ещё не реализованы.

## Текущее состояние

Реализован расчётный CLI-прототип, не готовое веб-приложение:
- генератор 2000 синтетических наблюдений и разбиение по конфигурациям;
- сравнение Ridge и Random Forest, сохранённые Pipeline, важность и SHAP;
- DEMATEL, MEREC, MARCOS, VIKOR и сравнение нормирования;
- 57 модульных тестов расчётного ядра;
- системный анализ и паспорт данных.

PostgreSQL, API, веб-интерфейс и мобильный канал ещё предстоит сделать.

## Сценарий использования
Выбор ноутбуков для офисных сотрудников, работающих
с документами, электронными таблицами, браузером и видеосвязью.

## Критерии выбора
- Цена — минимизация.
- Прогнозная производительность — максимизация.
- Масса — минимизация.
- Автономность — максимизация.
- Срок гарантии — максимизация.

## Дополнительные требования варианта
Сравнение способов нормирования.
Системный анализ: SSM (CATWOE и корневое определение),
модель Митчелла, DEMATEL.

## Основной сценарий работы
1. Пользователь создаёт проект выбора ноутбука.
2. Добавляет ноутбуки: характеристики, цену, массу,
   автономность и срок гарантии.
3. Система прогнозирует производительность с помощью
   обученной модели машинного обучения.
4. Система рассчитывает веса критериев методом MEREC.
5. Методы MARCOS и VIKOR формируют рейтинги ноутбуков.
6. Пользователь сравнивает результаты и влияние
   выбранного способа нормирования.
7. Пользователь выгружает отчёт с результатами.

Система помогает обосновать выбор.
Окончательное решение принимает пользователь.

## Запуск имеющегося прототипа

Из корня проекта с установленными зависимостями:

```powershell
python main.py
python -m pytest -q
python -m scripts.audit_project
```

`main.py` сравнивает сохранённую матрицу критериев. Он не запускает
сервер и не переобучает ML. Проверка audit_project загружает доверенные
модели из этого проекта, сверяет результаты и пишет JSON-отчёт.
Используйте версии из requirements.txt: сохранённые модели созданы
в scikit-learn 1.9.1; межверсионная совместимость joblib не гарантируется.

Системный анализ: docs/system_analysis.md. Паспорт: data/README.md.
Результаты проверки от 30.10.2026: docs/review_2026_10_30.md.
Следующий этап: техническое задание, архитектура PostgreSQL и API.
