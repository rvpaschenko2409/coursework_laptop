# Фоновое обучение Ridge и Random Forest

Этап ФТ-06, база master f3eaca4. Обучение запускается из проекта → «Обучение моделей», также ссылка добавлена на страницу «Данные для обучения». Результат сравнения доступен участникам проекта; запуск, отмена и активация — только аналитику.

## Подготовка

Установщик заменяет только файлы и делает резервную копию. Затем один раз выполните:

```powershell
.\.venv\Scripts\python.exe -m scripts.prepare_model_training
```

Пароль запрашивается для coursework_migrator. Применяется веб-миграция web0003: новая таблица web_training_runs, ограничения и индексы очереди. Версия ядра остаётся 0002. Повторная подготовка безопасна; существующие datasets, модели и результаты не заменяются. Непустой журнал обучения защищён от удаления при downgrade. Новые Python-пакеты не требуются.

Роль coursework_app получает SELECT/INSERT и ограниченный UPDATE состояния запусков, а для ml_models — только дополнительное UPDATE(is_active). Она не получает CREATE, административные права или право UPDATE пути/контрольной суммы модели. Веб-сервер поддерживает старые web0001/web0002 и новый web0003, но экран обучения требует web0003. Исторические скрипты подготовки прежних этапов, требующие именно web0002, после обновления повторно запускать не нужно.

Запуск сервера:

```powershell
.\.venv\Scripts\python.exe -m scripts.run_web
```

Этот пароль относится к coursework_app. Пароли не записываются в файлы и не включаются в журнал обучения.

## Данные и отсутствие утечки

Для выбранного набора берётся staging, при его отсутствии — processed. Исходный raw-слой с дефектами не используется. До постановки в очередь проверяются 20–10 000 строк, положительная конечная цель, аппаратные диапазоны и не меньше 10 конфигураций; постоянная целевая переменная отклоняется. В очередь помещается полный неизменяемый снимок проверенных строк и паспорта с SHA-256. Рабочий процесс повторно валидирует снимок и контрольную сумму.

Группы заново вычисляются по аппаратным признакам в прежнем порядке: cpu_cores, cpu_threads, cpu_frequency_ghz, ram_gb, storage_type, storage_gb. Они не зависят от пользовательского номера конфигурации или целевого балла. GroupShuffleSplit с test_size=0.2 откладывает 20% конфигураций. Внутри обучающей части GroupKFold(5) задаёт одинаковые блоки обеим моделям. Полный список назначений строк и групп сохраняется; пересечения проверяются явно.

В каждом блоке отдельно обучается Pipeline: StandardScaler для числовых признаков, OneHotEncoder(handle_unknown='ignore', sparse_output=False) для SSD/HDD, затем регрессор. Предобработка не обучается на тесте и не вычисляется заранее на всей выборке.

| Модель | Сетка параметров |
| --- | --- |
| Ridge | alpha: 0.1, 1, 10 |
| Random Forest | 200 деревьев; max_depth: 5 / None; min_samples_leaf: 1 / 5; random_state=seed |

Метрика подбора — средний MAE на пяти групповых блоках. Рекомендация между двумя моделями фиксируется по минимальному CV MAE до вычисления тестовых прогнозов. Затем обе выбранные версии один раз оцениваются на том же отложенном тесте: MAE, RMSE и R². Если цель на тесте постоянна, R² сохраняется как NULL и в интерфейсе объясняется причина; значение не подменяется фиктивной единицей. Тестовые метрики не определяют рекомендацию.

При исходных 2000 строках, seed 42 и нулевых дефектах повторяется разбиение 1608/392 строк, 80/20 конфигураций. Метрики сопоставлены с прежним экспериментом (см. checks.json); эта проверка не означает точность на реальных ноутбуках.

## Очередь и состояния

web_training_runs — специализированный долговременный журнал веб-обучения со снимком входов, seed, автором, source_dataset_id, request_key, состоянием, этапом, временем и результатом. Общая таблица jobs ядра этим модулем не изменяется. Ввод/идентичность запуска и завершённые записи защищены SQL-триггером от изменения.

Состояния: queued → running → succeeded / failed / interrupted / cancelled. Частичный уникальный индекс допускает одну активную задачу на проект. Общая очередь ограничена четырьмя задачами. PostgreSQL advisory lock разрешает только одному процессу вычислять обучение в рабочей схеме. Внутри одного сервера работает один фоновый поток, RF и GridSearchCV используют n_jobs=1; число потоков числовых библиотек ограничено единицей. Это ограничивает конкуренцию за ресурсы слабого ноутбука.

POST возвращает после фиксации очереди, не ждёт обучения; навигация остаётся доступной. Страница опрашивает краткий статус и обновляется при завершении. При проблеме соединения предлагает ручное обновление. Последние 50 запусков выводятся в интерфейсе; полная история остаётся в PostgreSQL.

Отмена проверяется между этапами, включая проверки перед записью. Текущий GridSearchCV не прерывается посередине fit; отмена не мгновенна. Остановка сервера завершает жизненный цикл потока; если процесс завершился во время обучения, при следующем запуске выполнявшиеся задачи помечаются interrupted. Очередь сохраняется и обрабатывается после старта. Прерванный опыт нужно запустить заново. Если инициатор потерял действующую роль аналитика, результат не регистрируется.

## Версии, артефакты и транзакции

Успех создаёт дочерний обработанный dataset, ссылающийся на исходный. В нём сохраняются processed-строки, parent row provenance, dataset_groups и train/test назначения. Первичный raw/staging не меняется. Повторение того же разделения может использовать уже созданный дочерний набор; каждая новая успешная задача создаёт новые версии двух моделей.

В ml_models сохраняются версия, параметры, CV-кандидаты, метрики, среда Python/NumPy/pandas/scikit-learn/scipy/joblib, SHA-256 кода обучения, снимок разделения, фактическая дата обучения и ссылка на dataset. Два Pipeline записываются в models/web/<UUID запуска>/<algorithm>.joblib с новыми именами, без перезаписи прежних файлов. В БД хранится SHA-256 точных байтов артефакта. Каталог models/web исключён из Git; для переноса/резервного копирования обученных моделей нужны и БД, и этот каталог. Старые models/ridge.joblib и models/random_forest.joblib продолжают поддерживаться.

Новые пути загрузчик принимает только по фиксированному шаблону UUID/algorithm внутри доверенного models; проверяет выход за каталог, симлинки, контрольную сумму, версию sklearn, тип Pipeline/регрессора и порядок признаков. Произвольные joblib от пользователя не загружаются.

Обработанный набор, две записи моделей, успешное состояние и аудит фиксируются одной транзакцией. Ошибка после регистрации откатывает все записи; непривязанные файлы удаляются. Сбой процесса может оставить временно неиспользуемый каталог; восстановление прерванного запуска удаляет его только при отсутствии ссылок на артефакты во всех проектах. Нельзя удалять файлы, используемые скопированным проектом.

## Явная активация

Обе новые версии сохраняются неактивными. «Сделать активной» проверяет доступ, CSRF, ревизию проекта и артефакт, затем в одной транзакции переключает единственную активную версию. Смена повышает ревизию проекта, чтобы формы и офлайн-синхронизация не ссылались на прежнюю модель незаметно.

Новая версия применяется при новых прогнозах через существующее добавление/редактирование альтернатив. Прежние оценки, predictions, ручные корректировки и результаты не перезаписываются. При последующем изменении ноутбука существующая история сохраняет ссылку на прежний прогноз. Отдельный массовый пересчёт текущих альтернатив и графические объяснения не входят в этот этап.

## Ручная проверка

1. В проекте №6 открыть «Обучение моделей».
2. Выбрать ранее загруженный чистый набор с 2000 проверенными строками (не набор с дефектами и 1600 строками), seed 42.
3. Запустить сравнение. Во время выполнения перейти на список проектов и вернуться: навигация должна работать.
4. Дождаться двух моделей, рекомендации по CV, train/test 1608/392, групп 80/20, пересечений 0.
5. Проверить совпадение тестовых метрик с прежним опытом: RF MAE 40.1206, RMSE 52.6125, R² 0.9671; Ridge MAE 62.4718, RMSE 76.5013, R² 0.9305 (округление до четырёх знаков).
6. Сделать рекомендуемую версию активной. Проверить, что обновление страницы сохраняет состояние. Добавить тестовый ноутбук через существующую форму и увидеть прогноз ML.
7. После ручной проверки запустить pytest, git diff --check, git status --short --branch; оформить коммит отдельно.

Автоматические проверки: tests/test_model_training.py и полный набор проекта; протокол web_model_training_checks.json. Windows-установка и пользовательская приёмка отмечаются pending до сообщения студента. Следующий отдельный этап — объяснение прогнозов и графические важности; курсовая целиком ещё не объявляется завершённой.
