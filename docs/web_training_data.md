# Загрузка обучающих данных через веб-интерфейс

Этап ФТ-05: CSV/XLSX → проверка → подтверждение → PostgreSQL. Обучение и выбор новой активной модели не входят в этот этап.

## Работа пользователя

На странице проекта для аналитика появилась ссылка «Данные для обучения». Доступны CSV- и XLSX-шаблоны, паспорт источника, сводка качества, первые 10 строк и список сохранённых наборов. Часовой пояс отображения — Asia/Omsk, как у остальных страниц.

Обязательные признаки: cpu_cores, cpu_threads, cpu_frequency_ghz, ram_gb, storage_gb, storage_type. Целевой столбец — performance_score. Для синтетики вместо него принимается synthetic_score; оба одновременно запрещены. Необязательные столбцы: sample_id, configuration_id, data_origin. Лишние столбцы отклоняются. Полностью пустые строки пропускаются, внешние пробелы значений удаляются.

Пределы: файл 20 МиБ, 10 000 непустых строк, аппаратные значения в диапазонах существующего валидатора. Подтверждение разрешается от 20 проверенных строк и 10 конфигураций. Формулы, макросы, внешние связи, даты Excel, объединённые ячейки и многостраничные книги не принимаются. CSV: UTF-8 (BOM допустим) или Windows-1251; запятая, точка с запятой или табуляция. XLSX распаковывается с ограничениями на части и суммарный объём.

Паспорт: название, происхождение synthetic/open/manual, URL, лицензия/условия использования, цель загрузки. Для open обязательны URL и лицензия, для synthetic — seed и имя/версия генератора. Это декларация загрузившего пользователя, а не независимое подтверждение лицензии или происхождения. URL не скачивается. Пароли в URL не принимаются.

## Качество и происхождение

До сохранения показываются:

- число исходных, проверенных и исключённых строк, полных дубликатов и конфигураций;
- числа текстовых, числовых, пустых и нечисловых NaN/Infinity значений по столбцам;
- пропуски, некорректные ячейки, минимумы/медианы/максимумы;
- число описательных выбросов по правилу 1.5 IQR для каждого числового столбца;
- первые 100 замечаний к строкам, первые 10 исходных строк и SHA-256 файла.

Некорректные строки и полные дубликаты исключаются только из проверенного слоя; в исходном они сохраняются. Пропуски не заполняются, целевые значения не генерируются и не заменяются прогнозом. Выбросы IQR автоматически не удаляются и не обрезаются. Повторяющиеся sample_id с разными данными блокируют сохранение. Совпадающая аппаратная конфигурация с разными измерениями остаётся несколькими наблюдениями.

configuration_id вычисляется как SHA-256 канонического JSON шести аппаратных признаков. Группа не зависит от пользовательского идентификатора и целевого балла; одинаковое оборудование получает одну группу. Разделение train/test и кросс-валидация выполняются позднее при обучении. На данном этапе нет processed-слоя и dataset_groups: назначения split не выдумываются заранее.

## Хранение

Новый datasets содержит паспорт, SHA-256 оригинальных байтов файла, quality_report и generation_params с версией импорта, именем файла, признаками, целевой переменной, семантическим SHA-256 проверенных строк и отметкой split_assigned=false. В dataset_rows записываются raw (разобранные строковые значения, не точная копия байтов файла) и staging (типизированные проверенные значения). provenance сохраняет строку источника и для staging — группу оборудования. Сама исходная книга на диск не записывается.

Оба слоя, паспорт и событие web_training_data_upload записываются одной транзакцией, порциями по 500 строк. При ошибке откатывается весь импорт. Повторные подтверждения и повторная загрузка того же SHA-256 в один проект возвращают уже существующий набор; метаданные существующего набора не перезаписываются. Результаты, модели, прогнозы, матрица альтернатив и действующие критерии не изменяются.

До подтверждения данные живут в ограниченном кэше процесса: максимум 4 предпросмотра, суммарно 32 МиБ, срок 15 минут. Другой пользователь/проект не получает доступ по токену. Перезапуск сервера или вытеснение кэша требует повторной проверки. Страница подтверждения содержит только случайный токен, данные не помещаются в скрытые поля формы.

Все чтения и записи проверяют членство и роль аналитика; POST дополнительно проверяет CSRF. Проект блокируется при записи, ревизия перепроверяется. Ограничение тела 20 МиБ + 64 КиБ относится только к training-data/preview. Предел прежнего импорта ноутбуков остаётся 1 МиБ и 15 альтернатив.

## Установка и проверка

Новые зависимости, миграции и права не нужны после выполненного этапа управления проектами/критериями. Используются существующие права INSERT на datasets/dataset_rows и USAGE соответствующих последовательностей. Веб-сервер запускается от coursework_app, а не от владельца схемы.

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m scripts.run_web
```

Для ручной проверки создайте отдельный пустой проект «Проверка обучающих данных», откройте «Данные для обучения», загрузите существующий data/synthetic/laptops_synthetic.csv. Паспорт: synthetic, seed 42, генератор scripts/generate_synthetic.py (учебный исходный генератор), условия «Авторская учебная синтетика». Предпросмотр должен показать 2000 исходных и 2000 проверенных строк, 100 конфигураций. Подтвердите, перезагрузите страницу, проверьте сохранённый паспорт. Повторная загрузка не должна создавать второй набор.

Затем:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
 git diff --check
 git status --short --branch
```

Автоматические проверки: tests/test_training_data.py, прежние tests/test_alternative_import.py и весь набор тестов. Изолированная PostgreSQL используется только для тестов, рабочая база студента не участвует. Подробный протокол — web_training_data_checks.json. Проверку Windows проводит студент после установки; она не заявляется заранее пройденной.
