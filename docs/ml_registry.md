# Регистрация существующих моделей и прогнозов

Вариант 27. Начальная регистрация ML, версия 1, 30.10.2026.

## Назначение

Этап переносит результаты проверенного файлового эксперимента в PostgreSQL: один синтетический набор, разбиение по конфигурациям, версии Ridge и Random Forest и пять прогнозов для проекта A1–A5. Обучение и подбор параметров не выполняются. CSV, joblib-файлы, формула генератора и расчётные методы не заменяются.

Функции соответствуют части ФТ-05, ФТ-06 и ФТ-07 ТЗ и таблицам datasets/dataset_rows/ml_models/predictions/scores раздела 4.3 пособия. Это начальный импорт ранее выполненного эксперимента; загрузка произвольных пользовательских наборов, обучение из веб-интерфейса, переключение моделей через интерфейс и объяснение каждого прогноза SHAP ещё предстоят.

## Источники и проверки до подключения

Скрипт читает существующие файлы:

- `data/synthetic/laptops_synthetic.csv` — 2000 наблюдений, 9 столбцов, синтетическая цель;
- `data/processed/train.csv` и `test.csv` — 1608/392 строки и 80/20 конфигураций;
- `models/ridge.joblib`, `models/random_forest.joblib` — Pipeline с предобработкой;
- `results/model_comparison_cv.csv`, `model_comparison_test.csv`, `test_predictions.csv`, `selected_model.txt`;
- `results/decision/alternatives_with_predictions.csv` — контрольные прогнозы пяти ноутбуков;
- ранее созданные `data/demo/project.json` и исходные CSV альтернатив/DEMATEL;
- код генератора и обучения — для фиксации контрольных сумм версии расчётного процесса.

`data/demo/ml_reference.json` содержит контрольные суммы ранее проверенного проекта. До десериализации сверяется SHA-256 каждого joblib. Затем проверяются тип регрессора, порядок шести признаков, воспроизводимость сохранённых тестовых прогнозов и метрик с допуском 1e-8, параметры выбранной по CV модели и пять прогнозов альтернатив. Отличающийся артефакт не загружается. Это проверка доверенных локальных моделей проекта, а не форма загрузки файлов пользователем.

Для данных проверяются отсутствие пропусков, уникальность sample_id, соответствие train/test исходным строкам, положительные конечные признаки/цель, 100 конфигураций, отсутствие пересечения train/test и пяти блоков GroupKFold. Контрольная сумма содержимого не зависит от LF/CRLF; изменение значений или разбиения отклоняется. Контрольные суммы не доказывают реалистичность синтетики или точность на реальных ноутбуках.

## Хранение данных

Создаётся одна запись datasets с row_count=2000 и column_count=9. Физический SHA-256 исходного CSV фиксируется при первой регистрации. Дополнительно в generation_params сохраняются семантический SHA-256, seed=42, версия/хеш кода генератора и параметры логнормального шума. Смена только переводов строк может менять байтовый SHA-256 файла, сохраняя его семантическое содержимое; прежняя запись происхождения при повторном запуске не переписывается.

В dataset_groups — 100 конфигураций с единственной частью выборки. В dataset_rows — 4000 физических записей: 2000 исходных raw и 2000 проверенных processed. Это два представления одних наблюдений, не увеличение обучающей выборки до 4000. Raw сохраняет 9 исходных полей; processed — 10 полей, включая configuration_id, и внешнюю привязку к train/test. В provenance указываются источник, sample_id и синтетическое происхождение. Отдельный staging-слой не наполняется, поскольку импортируется уже проверенный чистый эталон; фиктивная очистка не заявляется.

Загрузка выполняется пакетными параметризованными `INSERT SELECT` через `jsonb_to_recordset`, по 500 строк за запрос. Это массовая загрузка учебного объёма, а не отдельный INSERT для каждого наблюдения. COPY, рекомендованный пособием для больших наборов, остаётся вариантом для будущего общего импортера.

## Версии моделей

Регистрируются версии 1 двух моделей. В ml_models хранятся dataset_id, шесть feature_names, synthetic_score, параметры регрессора, выбранные параметры GridSearchCV, MAE CV, тестовые MAE/RMSE/R², путь и SHA-256 артефакта, seed разбиения, полный манифест train/test и групп CV. Контрольный набор не используется для выбора модели: активна модель с минимальной сохранённой MAE CV — random_forest.

| Модель | MAE CV | MAE test | RMSE test | R² test | Активна |
| --- | ---: | ---: | ---: | ---: | --- |
| Ridge | 63,8219 | 62,4718 | 76,5013 | 0,9305 | Нет |
| Random Forest | 48,8768 | 40,1206 | 52,6125 | 0,9671 | Да |

Показатели относятся к условной синтетической зависимости. Они не подтверждают прогноз реальной скорости ноутбуков. Шесть входных полей включают взаимосвязанные характеристики; их наличие не означает шесть независимых причинных эффектов.

Исходная достоверная дата обучения артефактов неизвестна. Миграция `0002` разрешает trained_at=NULL и добавляет registered_at с фактическим временем регистрации. В environment явно указано training_timestamp_known=false и сохранено окружение проверки. Это не выдаётся за полностью известное историческое окружение обучения. При обучении новых моделей из приложения actual trained_at должен фиксироваться в момент обучения.

## Повторный запуск и история

Регистрация выполняется в одной транзакции после проверки проекта. Все строки, модели, прогнозы и оценки проверяются чтением из БД перед COMMIT. При ошибке импорт полностью откатывается. Settings хранит отпечаток начальной регистрации; действие добавляется в audit_events, где явно указан инициировавший процесс PostgreSQL-пользователь. Actor_id относится к существующему учебному владельцу проекта, а не обозначает вход через ещё не созданный интерфейс авторизации.

Повторный запуск возвращает существующие идентификаторы без новых строк. Если изменились проверенные файлы, модель, разбиение, текущие прогнозы или исходный проект, скрипт останавливается. Ручная корректировка прогноза сохраняется и не заменяется модельным значением. Этот скрипт не является универсальным механизмом обновления моделей: следующие обученные версии потребуют отдельного сервиса реестра.

Для последовательности «миграция и импорт» командный запуск использует session advisory lock, а импорт — транзакционную блокировку того же ключа. Пароль спрашивается getpass и хранится только в памяти процесса. Имя базы фиксировано: coursework_laptop; роль — coursework_migrator. Нормальная роль веб-приложения с меньшими правами будет настроена отдельно.

## Миграция и команды

Новые файлы добавляются в ветке feature/ml-registry. Миграция 0001 не изменяется. Установщик не перезаписывает файлы и не запускает SQL самостоятельно.

```powershell
python -m scripts.register_ml --check-files
python -m scripts.register_ml --upgrade
```

Первая команда не подключается к БД. Вторая запрашивает пароль, применяет Alembic до 0002 и выполняет регистрацию. Миграция и импорт — две отдельные транзакции: при неуспешном импорте схема может уже иметь версию 0002, а данные импорта будут отменены. После исправления причины команда запускается повторно.

После успешной регистрации:

```powershell
python -m scripts.register_ml
```

Ожидается created=false и прежние идентификаторы. Проверочные SELECT находятся в `sql/003_verify_ml.sql`. Начальный `seed_demo` после перехода к 0002 повторно не нужен: этот старый загрузчик предназначен для первоначального проекта при 0001, а не для сброса проекта с ML.

Обратная миграция разрешена только если в ml_models нет записей с неизвестной датой обучения. Она намеренно не подставляет выдуманное время. В обычном ходе курсовой downgrade не применяется.

## Проверки и оставшаяся работа

`docs/ml_registry_checks.json` фиксирует автоматические проверки в изолированной PostgreSQL 18.6, собранной в WebAssembly (PGlite), через TCP и psycopg. Проверяются пакетная запись реальных данных, связи прогнозов, повторный запуск, сохранность ручной правки и откат при ошибке. Это не проверка Windows-аутентификации или работы на компьютере студента; её дополняет фактический запуск после получения файлов. Тесты с TEST_DATABASE_URL используют отдельные случайные схемы; без тестового подключения три интеграционных теста проекта пропускаются.

Функциональность всего приложения на этом этапе не завершена. Далее требуются расчёты и журнал из БД, серверная авторизация и роли, веб-интерфейс, общий импорт и генератор с параметрами, обучение и объяснения в приложении, экспорт, PWA, испытания и итоговая документация.
