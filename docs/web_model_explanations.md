# Перестановочная важность и локальное объяснение SHAP

Этап ФТ-08. База master c105974 после фонового веб-обучения. Из проекта открывается «Объяснение прогнозов», из карточки ноутбука с prediction_id — «Объяснить прогноз». Ссылка также есть на странице обучения моделей.

## Подготовка

После установки файлов остановите прежний сервер и один раз выполните:

```powershell
.\.venv\Scripts\python.exe -m scripts.prepare_model_explanations
```

Вводится пароль coursework_migrator. Применяется веб-миграция web0004 и права приложения; ядро остаётся 0002. Старые таблицы, модели, оценки и результаты не заменяются. Повторная подготовка допустима. SHAP и Matplotlib уже входят в исходные requirements.txt; новых зависимостей сверх проекта не добавлено.

Затем `.\.venv\Scripts\python.exe -m scripts.run_web`, пароль coursework_app. Веб-сервер принимает web0001–web0004; для страницы объяснений требуется web0004. Подготовку старых завершённых этапов с проверкой именно web0002 повторять не требуется.

## Какой прогноз объясняется

Пользователь выбирает сохранённый прогноз, а не просто текущую активную модель. Сохраняются prediction_id, model_id/версия, SHA-256 артефакта и снимок характеристик именно этого прогноза. Pipeline повторно вычисляет значение, и оно сравнивается с сохранённым prediction.value. Несовпадение блокирует сохранение объяснения.

Активация другой версии не меняет старое объяснение. При ручной корректировке показываются отдельно текущая оценка, причина и исходный выбранный ML-прогноз: ручное решение не подменяется SHAP-вкладами. Таблица характеристик относится к снимку, а не к незаметно изменённому ноутбуку. Объяснение не меняет веса критериев, матрицу оценок, прогнозы, модели или рейтинги.

## Проверка исходного разделения

Берутся только processed-строки dataset, к которому относится модель, с сохранёнными train/test. Поддерживаются исходные зарегистрированные модели и новые версии веб-обучения. Проверяются:

- допустимые признаки и цель, число наблюдений и конфигураций;
- отсутствие общих configuration_id и одинакового оборудования между train/test;
- совпадение групп и назначений строк со split_manifest модели (для старого формата — test_sample_ids);
- воспроизведение test_mae по всем сохранённым тестовым строкам;
- контрольная сумма и структура доверенного Pipeline через существующий загрузчик.

Если набор или метрика не воспроизводятся, вычисление останавливается с сообщением, а результат не записывается. В снимке остаются идентификаторы и SHA-256 dataset, полных строк и split_manifest, исходная полная test_mae, версии библиотек и SHA-256 UTF-8-кода объяснения.

## Перестановочная важность

sklearn.inspection.permutation_importance вызывается для полного Pipeline на отложенном тесте: scoring='neg_mean_absolute_error', 30 повторов, random_state=42, n_jobs=1. Перемешивается один исходный признак; предобработка и регрессор не переобучаются.

Показатель — рост MAE относительно исходной ошибки. Сохраняются все 30 значений, среднее и стандартное отклонение. На диаграмме горизонтальные полосы показывают средний рост, погрешности — ±1 стандартное отклонение, не доверительный интервал. Отрицательная важность допустима и не обрезается.

Для слабого ноутбука ограничено число тестовых строк: максимум 500. Если тест больше, используется фиксированная случайная подвыборка с seed 42 и сохраняются её номера строк. Интерфейс явно различает количество использованных/всех тестовых строк, MAE подвыборки и MAE полного теста. До подвыборки метрика модели перепроверяется на полном тесте. Для исходных 392 тестовых наблюдений используются все строки и результат совпадает с прежним scripts/feature_importance.py.

## SHAP

Для Random Forest используется TreeExplainer(feature_perturbation='tree_path_dependent', model_output='raw', check_additivity=True) для преобразованной записи. База определяется обучающими путями деревьев, строки теста не используются как опорная выборка.

Для Ridge используется LinearExplainer с Independent-маскером: до 100 воспроизводимо выбранных строк только из train, seed 42. Опорные строки и метод сохраняются. Это независимая постановка SHAP, не моделирование корреляционной причинности.

Сначала проверяются имена преобразованных признаков. Пять числовых SHAP-вкладов оставляются отдельно, все OneHot-индикаторы storage_type складываются в один вклад. Поэтому в таблице и диаграмме представлены шесть исходных признаков, а не отдельные фиктивные признаки HDD/SSD.

Сохраняются база, прогноз Pipeline, сохранённое значение prediction, шесть вкладов, восстановленное значение и абсолютное расхождение. Проверки np.isclose используют atol=1e-6, rtol=1e-8; неконечные значения отклоняются. Положительные вклады повышают прогноз относительно базы, отрицательные понижают. Причинное влияние характеристик из этого не следует; коррелирующие признаки могут делить важность.

Контрольный T1 (4 ядра, 8 потоков, 2.5 ГГц, RAM 8 ГБ, SSD 512 ГБ), исходная RF-модель: прогноз 989.7063359996, база 1031.8817668221395; расхождение суммы около 2.27e-13. Ridge также прошла проверку аддитивности, расхождение около 1.14e-13. Это контрольные локальные вычисления, не приёмка установленного сайта Windows.

## Хранение и доступ

web_model_explanations содержит project/model/prediction, автора, fingerprint, context_hash, input_snapshot, output и время. Роль coursework_app получает SELECT/INSERT и USAGE последовательности, но не UPDATE или DELETE таблицы. Исходные predictions остаются неизменяемыми.

Повторение того же снимка возвращает сохранённое объяснение. Глобальная важность повторно используется для других прогнозов той же модели только при полном совпадении контекста модели/набора/метода/версий. Изменение данных или кода даёт иной контекст. Два одновременных тяжёлых расчёта в рабочей схеме не запускаются: advisory lock возвращает понятное сообщение о занятом расчёте. Вычисление идёт в threadpool; цикл HTTP-сервера не занят вычислением SHAP. Лимит формы остаётся 8 КиБ.

Все страницы, JSON и PNG требуют действующего доступа к проекту. POST дополнительно проверяет CSRF; право доступа перепроверяется перед записью. На время вычисления проект защищается KEY SHARE от удаления, проектные действия с блокировкой ждут окончания короткого расчёта. Совпадение fingerprint защищено уникальным ограничением; результат и событие аудита записываются одной транзакцией.

При удалении альтернативы исходный прогноз может быть удалён существующим архивированием. В этом случае FK обнуляет только prediction_id объяснения; идентификатор, характеристики и значение остаются в неизменяемом input_snapshot. Историческая страница и графики продолжают открываться. Удаление самого проекта удаляет его объяснения каскадно. Копирование входов проекта не копирует историю объяснений.

## Графики и экспорт

Интерфейс показывает перестановочную диаграмму и SHAP waterfall, точные числовые таблицы и проверку суммы. PNG строятся из сохранённых чисел без повторного SHAP. Размер 1400×756, поддерживаются русские подписи и положительные/отрицательные вклады. Оба PNG можно скачать для отчёта. Доступен полный JSON-снимок. Никакие артефакты joblib не публикуются в static и не загружаются от пользователя.

1. Открыть проект №6, карточку T1 «Проверка новой ML-модели».
2. Нажать «Объяснить прогноз», затем «Рассчитать важность и SHAP».

4. Проверить две диаграммы, таблицы и скачивание PNG/JSON. Обновление должно открывать тот же сохранённый результат.
5. После ручной проверки выполнить pytest, git diff --check и git status --short --branch. Git-коммит создаётся отдельно.

Протокол автоматических проверок — web_model_explanations_checks.json. Там отдельно отмечены локальные проверки аддитивности, PNG и SQL/ролей; Windows-приёмка до сообщения студента остаётся pending. Курсовая целиком ещё не объявляется завершённой.
