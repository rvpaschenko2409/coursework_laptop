# Загрузка демонстрационного проекта

Вариант 27. Дата: 30.10.2026. Этап после миграции 0001.

## Состав демонстрации

Загружаются один проект закупки, пять критериев, пять вымышленных ноутбуков A1–A5, двадцать исходных оценок, 25 элементов матрицы DEMATEL, четыре заинтересованные стороны, CATWOE и корневое определение. Бюджет — 100000 рублей за устройство. Все цены, характеристики и оценки относятся к учебному сценарию и не выдаются за рыночные наблюдения или опрос реальных экспертов.

Источник ноутбуков — существующий `data/decision/alternatives.csv`. Источник влияний — существующий `data/decision/dematel_direct.csv`. Участники и оценки Митчелла перенесены из `docs/system_analysis.md` в `data/demo/project.json`. Порядок критериев согласован с `decision_core/criteria.py`: цена, производительность, масса, автономность, гарантия. Методы расчёта и сохранённые файлы результатов не изменяются.

В таблице `scores` на этом шаге заполнены только четыре критерия для каждого ноутбука: цена, масса, автономность и гарантия. Источник `manual` означает ручной ввод исходных сведений учебного сценария, а не реальные измерения. Критерий производительности имеет источник `ml`, но его пять значений пока отсутствуют. Старые прогнозы из CSV не записываются как ручные оценки и не заменяются нулями.

Следующий этап — регистрация существующих наборов данных и версий моделей, создание `predictions` и заполнение оставшихся пяти оценок со ссылкой на модель. Только после этого матрица будет полной для повторного расчёта MEREC/MARCOS/VIKOR в БД. Сейчас таблицы `datasets`, `ml_models`, `predictions` и `results` загрузчик не наполняет; ранее рассчитанные CSV и модели остаются на месте.

## Пользователи и роли

Создаются три служебные демонстрационные записи приложения: аналитик, ИТ-эксперт и руководитель. Они имеют адреса в `example.invalid`, `is_active=false` и заведомо нерабочую строку `!demo-disabled:` вместо пароля. Войти через них нельзя; общий предустановленный пароль не создаётся. Это участники сценария для внешних ключей и ролей, а не реализованная авторизация. В будущем доступ предоставляется зарегистрированному пользователю через отдельный сценарий приложения.

`coursework_migrator` — роль PostgreSQL, используемая для этой начальной загрузки и миграций. Она отличается от записей `users` приложения. Пароль вводится через getpass, не записывается в проект, JSON, Git или отчёт. Роль приложения с ограниченными правами будет настроена при подключении веб-сервера.

## Повторный запуск и транзакции

`settings.demo_key` определяет демонстрационный проект, `demo_fingerprint` хранит SHA-256 канонического содержимого, `demo_revision` — ревизию после загрузки. Отпечаток рассчитывается по разобранным данным, поэтому переводы строк LF/CRLF не меняют его. Одновременные запуски загрузчика сериализуются транзакционной advisory-блокировкой.

Первый запуск выполняет все INSERT и проверку результата в одной транзакции. Сообщение об успехе печатается только после COMMIT. Ошибка отменяет все изменения этого запуска. Другие проекты не изменяются. У уже существующих учебных пользователей не меняются пароли и состояние; если адрес занят другой учётной записью, загрузка отменяется.

Повторный запуск при том же содержимом проверяет БД и возвращает идентификатор существующего проекта. Новые пользователи, оценки, влияния и записи аудита не создаются. Если изменились исходные файлы или проект уже отредактирован в БД, загрузчик останавливается и не перезаписывает данные. Это намеренное ограничение начального загрузчика: он не является механизмом обновления пользовательских проектов. После добавления ML-прогнозов предметная демонстрация также считается изменённой; повторное заполнение или сброс таким скриптом не выполняется.

## Запуск

1. Добавить новые файлы установщиком в ветке `feature/demo-data`.
2. Проверить локальные файлы:

```powershell
python -m scripts.seed_demo --check-files
```

3. Загрузить проект, введя ранее заданный пароль PostgreSQL-роли coursework_migrator:

```powershell
python -m scripts.seed_demo
```

По умолчанию используются localhost, порт 5432, база coursework_laptop. При другом порте применяется `--port`; имя базы и роль специально фиксированы для этого учебного проекта. Для первой загрузки требуется миграция 0001.

4. Повторить ту же команду до подключения ML и убедиться, что дубликаты не созданы.
5. В pgAdmin выполнить `sql/002_verify_demo.sql` в базе coursework_laptop. Скрипт содержит только SELECT.

Новые зависимости не нужны: psycopg 3 уже установлен. Сервер приложения, работающий от другой роли, этот начальный загрузчик автоматически не запускает.

## Проверки

Автономные тесты проверяют состав демонстрации, явную маркировку синтетики, отсутствие ложных прогнозов, устойчивость отпечатка к переводам строк, запрет неконечных/неположительных значений, повторов альтернатив и ненулевой диагонали DEMATEL.

Интеграционный тест создаёт случайную отдельную схему в тестовой БД, применяет начальный DDL, вызывает реальный Python-загрузчик через psycopg, затем проверяет повторный запуск, неизменность ручных правок, откат неуспешной загрузки и отсутствие дубликатов. В конце удаляется только созданная им временная схема. Для него нужен `TEST_DATABASE_URL` и право создавать тестовые схемы; он не запускается автоматически в рабочей базе.

Протокол разработки: `docs/demo_data_checks.json`. Тестовая PostgreSQL работает в WebAssembly (PGlite) через TCP и psycopg; это не установка на компьютере студента. Проверка реальной загрузки в Windows выполняется студентом после получения файлов. Полная авторизация, обучение, прогнозы, импорт произвольных наборов и интерфейс ещё не реализованы.
