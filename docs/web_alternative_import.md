# Импорт ноутбуков из CSV и Excel

Основа: master ea62e85 после управления критериями. Ветка feature/web-alternative-import.

## Работа пользователя

Аналитик открывает проект → «Импорт CSV / Excel».

1. Скачать CSV- или Excel-шаблон. Заголовки сформированы по текущим действующим критериям проекта.
2. Заполнить новые ноутбуки. Столбцы: code, name, необязательный description, шесть аппаратных характеристик и все ручные критерии.
3. Выбрать файл, написать причину и нажать «Проверить файл».
4. Просмотреть строки, ошибки, предупреждения и прогнозы. На этом этапе в БД не добавляются ноутбуки, оценки и прогнозы.
5. Подтвердить добавление всей таблицы. Если есть ошибка, сначала исправить файл и проверить заново.

Импорт добавляет только новые альтернативы. Существующие коды и повторы внутри файла отклоняются. После импорта в проекте должно быть не больше 15 ноутбуков. Обновление сохранённого ноутбука выполняется через его обычную форму с причиной изменения.

Форматы: .csv и .xlsx. Старый двоичный .xls не поддерживается. CSV читается в UTF-8 (в том числе BOM) или Windows-1251; разделители: точка с запятой, запятая, табуляция. Десятичная запятая допускается. Excel: один видимый лист, первая непустая строка — заголовки. Формулы заменяются значениями перед загрузкой; макросы, внешние связи, объединённые ячейки, даты и логические значения не импортируются.

Не нужно заполнять performance_score: производительность считает активная модель по аппаратным характеристикам. Заготовленные прогнозы и рейтинги из файла отклоняются как неизвестные столбцы. Если активной модели нет, пользователь видит предупреждение: сохраняются характеристики и ручные оценки, производительность остаётся пустой. Ручная корректировка прогноза доступна после импорта через существующий редактор с сохранением основания.

Оценки проверяются теми же правилами, что в форме ноутбука. Бюджет не запрещает сохранение: превышение показано предупреждением и затем обрабатывается обычным бюджетным фильтром. Дополнительные ручные критерии обязательны для каждой строки. После изменения состава критериев нужно скачать новый шаблон.

## Сохранение и контроль

Предпросмотр подписан серверным HMAC-SHA256 и связан с пользователем, проектом, ревизией, активной моделью и SHA-256 файла. Он действует 15 минут; перезапуск сервера делает неподтверждённый предпросмотр недействительным. Пароли и ключ подписи не записываются в файлы.

Подтверждение повторно проверяет сессию, роль аналитика, CSRF, Origin, доступ к проекту, ревизию, модель, строки и ограничения. Проект блокируется на время операции. Все ноутбуки, их оценки, прогнозы и события аудита добавляются одной транзакцией. При ошибке после начала записи откатывается вся таблица. Повторное подтверждение того же успешного предпросмотра возвращает прежние идентификаторы без дублирования.

Используется существующий alternative_store.save, поэтому прогнозы ссылаются на зарегистрированную модель, характеристики сохраняются в снимке прогноза, а изменения проекта учитываются ревизией. Итоговое событие web_alternative_import содержит имя и SHA-256 исходного файла, число строк, идентификаторы созданных альтернатив, автора, причину, исходную ревизию и сведения о модели. Исходный файл не сохраняется на диске сервера.

Размер файла ограничен 1 МиБ, тела запроса — 1 114 112 байт только для preview/confirm. Остальные лимиты форм не увеличиваются. Разбор Excel ограничен по размеру распакованных данных, числу частей, строк, столбцов и ячеек; DTD и сущности отклоняются. Загруженный код не исполняется. Значения отображаются через экранирование Jinja2.

Новых Python-пакетов, разрешений PostgreSQL, таблиц и миграций нет. Используются разрешения предыдущих этапов. Импорт не меняет файлы моделей, обучающие данные, существующие альтернативы и сохранённые результаты.

## Приёмочная проверка

1. Создать копию исходного проекта № 1 с пятью критериями и пятью ноутбуками. Назвать «Проверка импорта».
2. Открыть «Импорт CSV / Excel», выбрать examples/example_laptops.csv из распакованного архива.
3. Причина: «Импорт учебных предложений». Проверить две строки B1/B2 и числовые прогнозы; до подтверждения ноутбуков должно оставаться пять.
4. Подтвердить. В копии должно стать семь ноутбуков, у B1/B2 — прогнозы ML.
5. Проверить расчёт MEREC при v=0,5, затем Excel-экспорт.
6. Повторная загрузка того же CSV должна показать занятые коды и ничего не добавить.
7. Для независимой проверки XLSX создать другую копию и импортировать examples/example_laptops.xlsx. Это те же две учебные записи, поэтому в один проект их дважды не добавляют.
8. Для проверки ошибки использовать examples/example_laptops_errors.csv: одна из строк содержит неверную массу. Весь файл должен быть отклонён без частичного добавления.

Обе записи в примерах вымышленные; это проверка интерфейса, а не предложения реальных продавцов. Образцы подходят для исходных пяти критериев. Для проекта с дополнительными критериями нужно заполнить их значения в шаблоне проекта.

Команды:

```powershell
.\.venv\Scripts\python.exe -m scripts.run_web
.\.venv\Scripts\python.exe -m pytest -q
```

Интеграционные тесты требуют отдельной тестовой PostgreSQL в TEST_DATABASE_URL. Рабочую БД курса для этих тестов не использовать.
