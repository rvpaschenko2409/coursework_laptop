# DEMATEL, CATWOE и корневое определение в браузере

Курсовая работа, вариант 27. Этап от 30.10.2026. Реализуется веб-часть ФТ-08а технического задания.

## Назначение и права

На странице проекта появилась ссылка «DEMATEL и модель задачи». Участники читают модель задачи и сохранённые результаты. Аналитик редактирует CATWOE и корневое определение, выбирает экспертные матрицы и запускает DEMATEL. Эксперт и аналитик вводят только собственную матрицу. ЛПР не может изменять оценки и запускать расчёт.

| Действие | Аналитик | Эксперт | ЛПР |
|---|---|---|---|
| Просмотр CATWOE и результатов проекта | Да | Да | Да |
| Изменение CATWOE и корневого определения | Да | Нет | Нет |
| Сохранение собственной матрицы | Да | Да | Нет |
| Запись от имени другого эксперта | Нет | Нет | Нет |
| Выбор источников и запуск DEMATEL | Да | Нет | Нет |

Проверки выполняются на сервере; скрытие кнопок не заменяет авторизацию. Используются членство в проекте, CSRF, параметризованный SQL и экранирование HTML. Чужие идентификаторы результатов, диаграмм и снимков не дают доступа. Архивный проект доступен только для чтения.

## Модель задачи

Редактор хранит C, A, T, W, O, E и корневое определение в существующих полях projects. Для каждого элемента CATWOE предусмотрено до 500 символов, для корневого определения — до 1500. Причина сохранения длиной 3–500 символов обязательна. Введённый текст и прежнее состояние записываются в audit_events с фактическим пользователем сессии. Повтор без изменений не повышает ревизию.

Форма определения принимает до 64 КиБ, чтобы указанные ограничения поддерживали URL-кодирование русского текста и других Unicode-символов. Для остальных форм сохраняется предел 8 КиБ. Нулевые и недопустимые управляющие символы отклоняются. Редактор сохраняет введённые значения при ошибке. Просмотр модели задачи доступен всем участникам; изменение — аналитику.

DEMATEL математически может быть рассчитан до заполнения описательной модели. В таком снимке незаполненные поля явно показаны как «Не заполнено». Это не означает завершение системного анализа.

## Экспертные матрицы

Текущий состав критериев определяется по идентификаторам PostgreSQL и устойчивому порядку sort_order/id. Модуль DEMATEL поддерживает 2–10 критериев, хотя общий редактор проекта и рейтингов пока использует исходные пять. В таблице C1–Cn обозначают критерии из легенды. Строка влияет на столбец.

Оценки целые: 0 — влияния нет; 1 — слабое; 2 — среднее; 3 — сильное; 4 — очень сильное. Диагональ равна нулю. Сервер требует всю квадратную матрицу, отклоняет чужие критерии, лишние поля, повтор полей, нечисловые, дробные и выходящие за шкалу оценки. expert_id берётся из сессии, а не формы.

Сохранение изменяет только строки comparisons текущего участника. Чужая матрица не копируется автоматически и не перезаписывается. Причина и прежние оценки сохраняются в аудите. Изменяются только отличающиеся ячейки; повтор той же матрицы не повышает ревизию. Полная нулевая матрица может быть сохранена как суждение «нет влияний», но её расчёт отклоняется: невозможно выполнить нормирование.

Матрица демонстрационного источника «Учебный ИТ-эксперт» — вымышленный контрольный пример прежнего этапа. Этот аккаунт отключён и не может войти. Аналитик может явно выбрать сохранённый учебный источник; интерфейс показывает его происхождение и неактивность. Старые оценки не приписываются текущему пользователю. Автор нового расчёта — фактический аналитик, выбранные авторы матриц хранятся отдельно.

## Агрегирование и вычисления

Аналитик выбирает 1–20 полных матриц. Каждая должна содержать оценки ровно для текущего набора критериев. Используется арифметическое среднее с одинаковыми весами экспертов. Сначала усредняются прямые оценки A, затем выполняется один расчёт DEMATEL. Дробные значения усреднённой A допустимы, хотя индивидуальные оценки целочисленны.

Вычисления делегированы неизменной функции decision_core.dematel.calculate_dematel:

- делитель s — максимум среди сумм строк и столбцов A;
- N = A/s;
- T = N(I − N)⁻¹, через решение системы, без явного обращения матрицы;
- D — суммы строк T, R — суммы столбцов T;
- D + R — вовлечённость, D − R — баланс влияния.

Дополнительная численная проверка веб-модуля требует спектральный радиус N меньше 1 с запасом 10⁻¹², чтобы погрешность вычисления собственного числа около единицы не создавала ложную сходимость. Проверяются конечность результатов, равенство сумм D и R при просмотре показателей; выводится невязка T − NT − N. Нулевая и несходящаяся матрицы дают понятную ошибку и не создают результата.

Классификация использует допуск 10⁻⁹: D − R выше допуска — «Источник», ниже отрицательного допуска — «Получатель», иначе «Нейтральный». Эти названия относятся к структуре экспертной модели. Они не доказывают статистическую причинность и не подтверждают реальное влияние оборудования.

Нормированные (D + R)/Σ(D + R) показаны как отдельные предлагаемые веса. Они не заменяют автоматически веса MEREC и не меняют сохранённые рейтинги MARCOS/VIKOR. Выбор и комбинирование систем весов относятся к следующему этапу.

## Диаграммы и контроль

Python/Matplotlib строит карту по координатам (D + R, D − R) и направленный граф полного влияния T. Узлы C1–Cn расшифрованы в таблице. В графе показываются только внедиагональные связи строго выше порога. По умолчанию порог — среднее внедиагональных значений T. Аналитик может задать конечное значение 0–10⁹. Порог влияет только на набор показанных связей; T, D, R и предлагаемые веса от него не меняются. При отсутствии связей диаграмма сообщает об этом.

Для исходного примера делитель равен 8, спектральный радиус — 0; T совпадает с N. Контрольные значения:

| Критерий | D | R | D + R | D − R |
|---|---|---|---|---|
| Цена | 0 | 0,625 | 0,625 | −0,625 |
| Производительность | 1 | 0 | 1 | 1 |
| Масса | 0 | 0,25 | 0,25 | −0,25 |
| Автономность | 0 | 0,375 | 0,375 | −0,375 |
| Гарантия | 0,25 | 0 | 0,25 | 0,25 |

Суммы D и R равны 1,25. Это контроль вымышленной матрицы, не результат обследования реальной организации. Изменение экспертных оценок закономерно изменит показатели.

## Снимки, конфликты и история

Перед изменением или запуском блокируется строка проекта, повторно проверяется роль и сверяется ревизия формы. Устаревшая форма получает 409. Вставка structure_models и событие аудита выполняются одной транзакцией; ошибка после вставки откатывает обе записи. Успешный ответ отправляется после завершения транзакции.

Снимок содержит модель задачи, критерии и их идентификаторы, выбранных участников с индивидуальными оценками, правило усреднения, параметры графа, автора запуска и окружение. Сохраняются SHA-256 исходного модуля DEMATEL и логическая версия веб-обработки dematel-web-1. Повтор того же пользователя с тем же снимком возвращает прежний результат без дубля.

При чтении проверяются отпечаток, версия, ревизия и совпадение повторно вычисленного результата. Изменённые текущие CATWOE или оценки не подставляются в историю. Различие текущей и сохранённой ревизии отмечается как историческое состояние. Ревизия общая для проекта: изменение экспертной модели может пометить и прежний рейтинговый расчёт как относящийся к старой версии, даже если его числовая матрица не изменилась.

История показывает 20 результатов на страницу. Диаграммы и JSON-снимки требуют доступа к проекту и возвращаются с Cache-Control: no-store. Отображаемое время относится к Омску. Новые результаты нельзя изменять или удалять от имени coursework_app; предусмотрены только SELECT/INSERT в structure_models.

## Установка и проверка

Новые таблицы, миграции и зависимости не требуются. Версии схем остаются 0002 и web0002. Используются существующие comparisons, structure_models и поля projects. Coursework_app получает необходимые SELECT/INSERT/UPDATE(value) для матриц, SELECT/INSERT для результатов и USAGE на последовательность. DELETE матриц и UPDATE/DELETE результатов не выдаются. Разграничение проектов — серверное; PostgreSQL RLS не заявляется.

1. Остановить сервер: Ctrl+C и дождаться приглашения PowerShell.
2. Распаковать архив на рабочий стол в coursework_web_dematel.
3. В чистой ветке feature/web-dematel выполнить:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Desktop\coursework_web_dematel\install_web_dematel.ps1"
python -m scripts.prepare_web_dematel
```

Ввести пароль coursework_migrator. Установщик сохраняет четыре обновляемых файла в резервной папке рядом с проектом и проверяет их исходные контрольные суммы с учётом CRLF. Данные, модели, математические модули и старые результаты не заменяются. Затем запустить `python -m scripts.run_web`, ввести пароль coursework_app и открыть демонстрационный проект → «DEMATEL и модель задачи».

Для первого контроля достаточно выбрать полную учебную матрицу и нажать «Рассчитать DEMATEL». Сохранять новую личную матрицу или менять CATWOE для этого не нужно.

Проверка: `python -m pytest -q`. Тесты с TEST_DATABASE_URL используют отдельную тестовую БД и временные схемы/роли. Без адреса они явно пропускаются. В среде подготовки применяются PostgreSQL через PGlite, реальные SQL-права через SET LOCAL ROLE и Chromium на пяти ширинах 360, 390, 768, 1366, 1920 px. Нативная подготовка прав и запуск Windows/PostgreSQL подтверждаются после установки пользователем.

Этап не заявляет полное выполнение курсовой. Реестр заинтересованных сторон, применение и комбинирование весов, чувствительность, фиксация решения ЛПР, экспорт XLSX, импорт, обучение моделей, PWA и другие оставшиеся требования выполняются отдельно. Методический приёмочный сценарий не заменяется количеством тестов.
