# Управление проектами
Версия от 5 ноября 2026 года. Требование ФТ-02 таблицы 3.1 методического пособия.

## Действия
На странице проекта аналитику доступны «Настройки проекта», «Создать копию» и «Удалить проект».
Редактируются название, цель и необязательный положительный бюджет до 1 трлн рублей.
Название содержит от 2 до 200 символов, цель — до 2000. Поддерживается десятичная запятая.
Изменение настроек увеличивает ревизию существующим триггером. Предыдущие результаты помечаются устаревшими.
Если значения не меняются, ревизия не увеличивается.

Копирование создаёт проект в состоянии draft, владельцем становится выполняющий действие аналитик.
Копируются текущие критерии, альтернативы и оценки, участники, CATWOE, корневое определение,
заинтересованные стороны, прямые влияния DEMATEL, наборы данных с группами и строками,
зарегистрированные модели и прогнозы текущих оценок. Все связи переведены на новые идентификаторы.
Оригинальные даты обучения и авторы прогнозов сохраняются. Файлы моделей используются по прежним
проверяемым путям и контрольным суммам, повторное обучение для копирования не требуется.
Общий набор критериев и состав активной модели сохраняются.
Служебные метки demo_* и ml_registry_* не переносятся, поэтому команды seed_demo/register_ml
продолжают находить единственный исходный демонстрационный проект.
В событиях аудита сохраняются исходный проект, его ревизия и номер копии.

Копия начинается с текущих входных данных. Старые результаты, наборы рассчитанных весов, решения ЛПР,
история изменений оценок и архив удалённых альтернатив принадлежат исходному проекту.
Для копии следует выполнить новый расчёт. Состав копии описан прямо в форме перед подтверждением.
Роли участников переносятся, а автор копии получает роль аналитика. Вымышленные эксперты сохраняют
свои исходные атрибуты и не становятся активными реальными пользователями.

Удаление требует точного ввода текущего названия проекта. Каскад удаляет зависимые данные проекта,
включая расчёты, решения и проектный журнал аудита, согласно существующим внешним ключам.
Учётные записи пользователей и файлы общих моделей сохраняются. Резервная копия установщика
содержит исходный код, а не PostgreSQL. Для проверки удаления следует использовать созданную копию.

## Согласованность
Все изменения выполняются в транзакции соединения приложения. Используются серверная проверка
роли аналитика, CSRF и проверка Origin существующим модулем безопасности.
Формы содержат ревизию. После блокировки строки проекта сервер повторно проверяет доступ и ревизию.
Устаревшая форма возвращает 409. Пользователь другого проекта получает 404, эксперт и ЛПР — 403.
Копирование использует ключ запроса и событие аудита под блокировкой исходного проекта.
Повтор одного запроса возвращает ранее созданный проект. Изменение полей при повторном ключе
возвращает 409. При ошибке посередине копирования все вставки откатываются.
Метаданные моделей, прогнозы и оценки копируются без смены их происхождения.

## Подготовка
Из папки coursework_laptop выполнить:
python -m scripts.prepare_project_management
Команда запрашивает пароль coursework_migrator и выдаёт дополнительные точечные права
существующей роли coursework_app. Версии схем остаются 0002 и web0002.
Новые таблицы и миграции на этом этапе не требуются.
Затем запустить python -m scripts.run_web.
Для локального запуска через HTTPS используется ранее подготовленный launch_https.py.

## Испытания
В tests/test_project_management.py проверяются числовые ограничения,
редактирование, отдельные идентификаторы копии, повтор без дубликата,
полномочия и CSRF, конфликт ревизии, копирование данных и моделей,
перевязка прогнозов, расчёт скопированного проекта, каскадное удаление и откат
незавершённого копирования. Интеграционные тесты используют TEST_DATABASE_URL,
временную схему и отдельную непривилегированную роль.

На изолированном PostgreSQL 16.2 выполнены интеграционные тесты.
На пользовательской PostgreSQL 18 нужно применить права и выполнить ручной сценарий.
Предыдущая серия пользователя до обновления — 214 passed, 91 skipped, 1 warning.
Пропуски обозначают интеграционные проверки без TEST_DATABASE_URL.

Общий запуск на изолированном стенде PostgreSQL 16.2 завершился результатом 316 passed, 1 warning за 66,50 с. Пропусков нет. Предупреждение относится к совместимости pytest и AnyIO в среде проверки. Версии scikit-learn 1.9.1 и pandas 3.0.6 соответствовали проекту.
