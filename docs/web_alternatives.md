# Ввод ноутбуков и оценок через браузер

Курсовая работа, вариант 27. Этап от 30.10.2026.

## Реализовано

В проекте появились добавление, просмотр, редактирование и удаление ноутбуков. Редактор содержит название, уникальный код, описание, шесть признаков оборудования и четыре ручные оценки. Для проекта с активной зарегистрированной моделью производительность рассчитывается автоматически. Поддерживаются исходные пять критериев варианта; импорт CSV/XLSX и изменение состава критериев относятся к дальнейшим этапам.

| Роль в конкретном проекте | Возможности этапа |
|---|---|
| Аналитик | Добавление, изменение характеристик и оценок, корректировка прогноза с причиной, удаление и просмотр архива |
| Эксперт | Просмотр ноутбуков и изменение четырёх ручных оценок с причиной; без изменения характеристик, прогноза и состава альтернатив |
| ЛПР | Просмотр таблицы решений |
| Посторонний пользователь | Доступ к проекту и альтернативам запрещён |

Действия проверяются на сервере при каждом запросе. Роль не определяется кнопками страницы. Каждая альтернатива выбирается одновременно по идентификатору и проекту; подстановка идентификатора из другого проекта возвращает 404. POST-формы сохраняют защиту CSRF и ограничение тела 8 КиБ из предыдущего этапа. Поля формы не должны повторяться; эксперт не может прислать недоступные ему поля характеристик.

## Поля и проверка ввода

| Поле | Допустимые значения |
|---|---|
| Код | До 20 символов: первая латинская буква, затем латинские буквы, цифры, `_` или `-`. Регистр приводится к верхнему |
| Название, описание | 2–200 печатных символов; описание до 1000 символов |
| Ядра, потоки | Целые 1–128 и 1–256; потоков не меньше, чем ядер |
| Частота | 0,1–10 ГГц |
| ОЗУ | Целое 1–1024 ГБ |
| Накопитель | SSD или HDD; целое 16–65536 ГБ |
| Цена | 1–10¹² рублей |
| Масса | 0,1–20 кг |
| Автономность | 0,1–72 часа |
| Гарантия | Целое 1–120 месяцев |
| Причина | До 500 символов; обязательна при изменении, ручной корректировке и удалении |

Это широкие учебные границы формы, а не подтверждение существования всех комбинаций на рынке. Поддерживаются запятая и точка как десятичный разделитель. Пустые обязательные поля, NaN, бесконечности, дробные целочисленные поля и недопустимые сочетания отклоняются. Ошибка показывает поле, а форма сохраняет введённые значения. Если сохранение не состоялось, ни часть характеристик, ни часть оценок не записывается.

В черновике допустимо 0 или 1 ноутбук; существующий расчёт требует не менее двух допустимых альтернатив. Верхний предел ввода — 15 ноутбуков на проект. Цена выше бюджета допускается: бюджетный фильтр остаётся частью расчёта, а не скрытым изменением цены или исключением при вводе.

## Прогнозы и ручные корректировки

Используется активная модель этого же проекта, зарегистрированная предыдущим этапом. Разрешены только проверенные локальные Pipeline Ridge и Random Forest из `models/ridge.joblib` и `models/random_forest.joblib`. SHA-256 проверяется для тех же байтов, которые десериализуются. Дополнительно проверяются порядок шести признаков, тип Pipeline, регрессор и совместимость версии scikit-learn. Модель кэшируется в памяти при первом использовании по пути, контрольной сумме и алгоритму; новая версия получает отдельную запись кэша. Произвольные joblib-файлы через браузер не загружаются.

При изменении характеристик создаётся новая запись `predictions`. Предыдущая запись не переписывается. Ссылка на актуальный прогноз хранится в оценке `scores`. Если характеристики и активная модель прежние, исходный прогноз используется повторно. Пустая, неконечная или неположительная выдача модели отклоняется.

Режим «Ручная корректировка прогноза» требует положительного значения и причины. Оценка получает источник manual, сохраняет ссылку на исходный прогноз и отображается как «Скорректировано». Возврат к прогнозу активной модели также требует причины изменения. Существующий триггер `tr_scores_history` сохраняет старое и новое значения, источники, ссылку на прежний прогноз, пользователя и причину. На странице редактирования показаны последние 30 изменений оценок. Время в страницах истории и архива показано для Омска.

Оценки, которые не изменились, не переписываются; автор прежней оценки сохраняется. Повторное сохранение без изменений не повышает ревизию. Изменения характеристик, оценок и удаления записываются в audit_events с фактическим пользователем веб-сессии и снимками данных.

Текущие модели обучены на синтетике. Их баллы не являются Geekbench, измерением реальной скорости или подтверждением точности на реальных устройствах. Для конфигурации вне пяти учебных CPU-профилей, заданных уровней памяти и накопителя редактор показывает дополнительное ограничение. Допустимость полей формы не означает, что конфигурация входит в обучающий набор.

В новом проекте без активной модели сохраняются характеристики и четыре ручные оценки. Производительность остаётся незаполненной, что явно указано в редакторе и таблице. Такая матрица ещё не готова к расчёту. Подключение моделей к новым проектам через браузер относится к отдельному этапу. Готовый демонстрационный проект уже имеет активную модель.

## Конфликты и история расчётов

Формы содержат ревизию проекта. Запись блокирует строку проекта и повторно проверяет роль участника. Если данные изменились после открытия формы, сервер возвращает 409 и предлагает открыть форму заново. Подтверждённые изменения другого пользователя не перезаписываются автоматически. Проверка выполняется до изменения альтернативы и оценок.

Существующие триггеры PostgreSQL повышают ревизию проекта. На странице таблицы появляется сообщение, если последний успешный расчёт какого-либо метода относится к иной ревизии. Исторические результаты и их входные снимки не изменяются. Проверка воспроизведения старого MARCOS после изменения и удаления ноутбука входит в интеграционные испытания.

## Удаление

Удаление доступно только аналитику. Отдельная страница требует указать причину и точно ввести код ноутбука. Перед удалением в `web_deleted_alternatives` сохраняются полные характеристики, все текущие оценки, исходные и последующие прогнозы и история изменений оценок. Затем из текущих таблиц удаляются связанные строки. Все действия выполняются в одной транзакции.

Архив привязан к проекту и пользователю удаления. Веб-роль может добавлять и читать архивные записи, но не обновлять или удалять их. Аналитик видит последние 100 удалений и может открыть сохранённый снимок JSON. Автоматическое восстановление из архива на этом этапе не реализовано. Сохранённые результаты MARCOS/VIKOR продолжают воспроизводиться по собственным историческим снимкам.

## Миграция и установка

Цепочка ядра и таблица alembic_version остаются на 0002. Независимая веб-цепочка обновляется с web0001 до web0002. Добавляется одна таблица архива. После этапа — 24 прикладные таблицы и две служебные таблицы версий Alembic. Прежние миграции и файлы `decision_core` и `decision_store/calculations.py` не заменяются.

Новые права выдаются существующей роли coursework_app только на нужные операции и последовательности. Для создания записей истории и архивирования удаления ей необходимы соответствующие права на score_history, scores, predictions и alternatives. Изоляция проектов остаётся серверной; PostgreSQL RLS данным этапом не заявляется. Веб-роль не получает CREATE, права на изменение пользователей или владельца проекта, административные привилегии или возможность изменения архива.

1. Остановить веб-сервер в первом терминале сочетанием Ctrl+C.
2. Распаковать архив на рабочий стол в `coursework_web_alternatives`.
3. Во втором терминале проекта, в чистой ветке `feature/web-alternatives`, выполнить:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Desktop\coursework_web_alternatives\install_web_alternatives.ps1"
python -m scripts.prepare_alternatives
```

Последняя команда запрашивает пароль coursework_migrator, применяет веб-миграцию и обновляет права уже созданной coursework_app. Повторное выполнение не создаёт дублей. Дополнительные библиотеки сверх ранее установленных requirements.txt, requirements_database.txt и requirements_web.txt не требуются.

Установщик проверяет ветку, чистое состояние Git и контрольные суммы четырёх обновляемых файлов с учётом Windows-переносов строк. Прежние версии этих файлов сохраняются рядом с проектом в отдельной резервной папке. Данные, модели и результаты расчётов он не заменяет. Неизвестные изменения исходников не перезаписываются.

После подготовки:

```powershell
python -m scripts.run_web
```

Ввести пароль coursework_app, открыть `http://127.0.0.1:8000`, войти прежней веб-учётной записью и открыть демонстрационный проект. На странице появятся «Добавить ноутбук» и действия в таблице. Чтобы проверить интерфейс без изменения контрольной демонстрации, можно создать отдельный черновой проект; в нём пока не будет активной ML-модели.

## Проверка и границы этапа

```powershell
python -m pytest -q
```

Тесты с БД требуют TEST_DATABASE_URL на отдельной тестовой PostgreSQL и тестового администратора для временных схем и ролей. Без этого адреса они явно пропускаются. Для подготовки использованы PostgreSQL через PGlite, реальные SQL-права через SET LOCAL ROLE, HTTP-тесты и Chromium. Нативные миграция и запуск на Windows подтверждаются при установке пользователем.

Проверяется только описанный этап: CRUD ноутбуков, четыре ручные оценки, применение существующей активной модели, корректировки и история. Импорт CSV/XLSX, CRUD критериев, подключение и обучение моделей для новых проектов, веб-запуск методов принятия решений, экспорт, автономный режим и полное выполнение ТЗ ещё не заявляются.
