# Настраиваемая генерация обучающих данных

Этап ФТ-05а для варианта 27. База изменений — master f0a7771, после загрузки обучающих CSV/XLSX.

## Интерфейс

Аналитик открывает проект → «Данные для обучения» → «Сгенерировать синтетические данные». Задаются название, цель опыта, итоговое число строк 100–10 000, seed 0–2147483647, sigma логнормального шума 0–0.5 и три доли дефектов. Каждая доля 0–30%, сумма не больше 60%. Проверка параметров работает на сервере независимо от браузерных ограничений.

«Сгенерировать и проверить» показывает качество, формулу, происхождение, число внесённых дефектов и предпросмотр; данные в PostgreSQL ещё не записываются. Сохранение обоих слоёв выполняется отдельной кнопкой. Параметры, версия генератора и происхождение записываются приложением автоматически. Обучение и активация моделей не запускаются этим экраном.

## Формула и воспроизводимость

Генератор: web-laptop-generator-v1. Формула: laptop-toy-score-v1.

- C = (cores / 4)^0.7 × (GHz / 2.5).
- M = (RAM / 8)^0.3.
- D = 1.0 для SSD, 0.4 для HDD.
- T = 0.7 / C + 0.2 / M + 0.1 / D.
- target = round((1000 / T) × noise, 2), noise ~ Lognormal(-sigma²/2, sigma).

Это условная зависимость учебного генератора. Потоки и ёмкость накопителя сохраняются как признаки, но прямо не входят в целевую формулу. Характеристики не обозначают конкретные реальные модели процессоров. Метрики такого обучения не являются проверкой точности на реальных ноутбуках.

Основной поток NumPy default_rng/PCG64 повторяет последовательность прежнего scripts/generate_synthetic.py. Внесение дефектов использует отдельный поток SeedSequence([seed,271828]). При 2000 строк, seed 42, sigma 0.05 и нулевых дефектах значения каждой строки точно совпадают с прежним data/synthetic/laptops_synthetic.csv. Старый скрипт и исходный CSV не изменяются.

Для воспроизведения сохраняются все параметры, версии формулы/генератора, нормализованный SHA-256 кода генератора, версия NumPy, алгоритм RNG, правило округления, правила дефектов и SHA-256 сериализованного CSV. Надёжное повторение требует той же версии кода и среды; зависимости проекта фиксированы.

## Определение долей

Доли считаются от окончательного количества raw-строк, включая копии. Число каждого вида дефектов округляется до ближайшего целого, половины вверх. Объём исходной независимой генерации равен n_rows минус число копий. Из его строк без повторения выбираются непересекающиеся группы пропусков и выбросов. В конце добавляется заданное число копий неповреждённых базовых строк.

- Пропуск: одна случайная ячейка среди шести аппаратных признаков и целевого балла очищается. Идентификатор и data_origin не очищаются.
- Выброс: частота процессора умножается на 20. Получаются 40–60 ГГц, заведомо вне принятого доменного диапазона 0.1–10 ГГц. Это объявленный учебный вид дефекта, а не моделирование всех реальных выбросов.
- Дубликат: полностью копируется неповреждённая строка, включая sample_id. Источник копии записывается в provenance. Поле provenance не входит в критерий полного дубликата.

Уже реализованный валидатор загрузки формирует staging: исключает пропуски, недопустимую частоту и полные дубликаты. Истинные значения не восстанавливаются по формуле или меткам инъекции. Описательные отметки 1.5 IQR вычисляются по staging и не равны числу внесённых выбросов; IQR сам по себе не удаляет строки.

Пример: 2000 строк, пропуски 5%, выбросы 5%, дубликаты 10% → 100 + 100 + 200 дефектных строк, raw 2000, staging 1600. При seed 42 остаётся 100 конфигураций. Для каждой записи сохраняются synthetic, seed, версии, идентификатор исходного наблюдения, номер базового случайного наблюдения, итоговый номер записи и метка дефекта/источник копии. Staging сохраняет эти сведения для оставшихся строк. Группировка оборудования и будущий train/test не подменяются номерами строк.

## PostgreSQL и безопасность

Используются существующие datasets/dataset_rows с raw и staging, quality_report и generation_params. Миграции и дополнительные права не нужны после этапа управления проектами/критериями. Генерация не пишет файлы данных на диск; результат до подтверждения хранится в том же ограниченном кэше, что и загрузка: 4 предпросмотра, суммарно 32 МиБ, 15 минут. Токен связан с проектом, пользователем и ревизией; перезапуск/вытеснение требует повторной проверки.

Для генерации datasets.sha256 — SHA-256 канонического пакета «полный рецепт + исходные строки», а не SHA-256 CSV-файла. Контрольная сумма CSV сохранена отдельно как generation.content_sha256. Название и цель не входят в идентичность: тот же рецепт возвращает прежний набор без дубля и перезаписи паспорта. Смена seed, долей, sigma, объёма или версии создаёт иной набор. Для загружаемых файлов прежнее определение datasets.sha256 (байты файла) сохраняется.

Оба слоя, паспорт и аудит сохраняются одной транзакцией существующего подтверждения training-data/confirm. Код подтверждения повторно проверяет роль аналитика, CSRF, проект и ревизию. Ошибка после записи строк откатывает весь набор; подтверждение можно повторить. Для генерации действует обычный предел формы 8 КиБ, лимит CSV/XLSX не расширяется. Вычисление вынесено в threadpool, навигация не выполняет генерацию в цикле async-сервера.

Существующие модели, прогнозы, альтернативы и результаты не меняются. Версии схем остаются 0002/web0002. Графическое объяснение прогноза, веб-обучение и остальные ещё не выполненные требования курсовой не объявляются завершёнными этим этапом.

## Ручная проверка в Windows

1. Запустить `.\.venv\Scripts\python.exe -m scripts.run_web`.
2. Открыть проект №6, который использовался для проверки загрузки, и перейти к генератору.
3. Первый опыт: 2000 строк, seed 42, sigma 0.05, дефекты 0/0/0. Ожидается 2000 raw, 2000 staging, 100 конфигураций.
4. Второй опыт: 2000, 42, 0.05, пропуски 5, выбросы 5, дубликаты 10. Ожидается raw 2000, staging 1600, исключено 400, дубликатов 200; внесено пропусков 100, выбросов 100, копий 200.
5. Сохранить второй опыт, обновить страницу и проверить сохранённые параметры. Повторное создание с теми же параметрами и подтверждение не должны добавлять второй идентичный набор.
6. Запустить `.\.venv\Scripts\python.exe -m pytest -q`, `git diff --check`, `git status --short --branch`.

Протокол автоматической проверки — web_data_generator_checks.json. Испытания с PostgreSQL проходят в отдельной тестовой схеме от непривилегированной роли. Проверку установки и интерфейса Windows выполняет студент; до его сообщения она отмечена pending.
